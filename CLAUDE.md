## 1. What we are building

Henosis is an open-source CLI that takes a **native Android SDK** (an `.aar` file or Maven coordinates) plus a small config file, and generates **ready-to-run cross-platform packages**:

- a **Flutter plugin** (Dart API + Android plugin glue + example app)
- a **React Native module** (New Architecture TurboModule + TS API + example app)

One config, one command, no hand edits.

**Core idea: facade-first.** The user lists only the classes and methods they want exposed. Henosis reads their real signatures from the SDK, builds one **intermediate representation (IR)**, and every target generator reads only the IR. A new framework means a new generator, not a new tool.

```
.aar / Maven ──► Parser ──► Facade selection + doctor ──► IR (JSON)
                                                          │
                     ┌────────────────────┬───────────────┼────────────────────┐
                     ▼                    ▼               ▼                    ▼
              Kotlin bridge        Flutter target   React Native target   (MAUI, v0.2)
                     └────────────────────┴───────────────┴──► heno verify (builds example apps)
```

## 2. Hard rules

1. **Clean room.** Never copy code, assets, names or internal knowledge from any employer or client (ApataTech, Blatchford, SourceID, Caluu or others). Fixtures and demos use our own sample SDK or public open-source SDKs only.
2. **Deterministic output.** Same input means byte-identical output. Sort everything (classes, methods, fields, imports). No timestamps in generated files.
3. **Generated header.** Every generated file starts with a comment: `Generated by Henosis <version>. Do not edit.`
4. **Fail loudly, early.** Unsupported types are reported by `heno doctor` with file, member and a fix hint. Generation never emits code that silently drops a member.
5. **Scope discipline.** Anything in "Out of scope" goes in `docs/roadmap.md`, not the code.
6. **Use current stable versions** of every library and toolchain. Verify versions when you add a dependency; do not rely on remembered version numbers.

## 5. v0.1 scope

### In

- **Input:** local `.aar`, or Maven coordinates (`group:artifact:version`).
- **Facade config** in `henosis.yaml` (section 6).
- **Types:** see section 7.
- **Async:** Kotlin `suspend fun` → Dart `Future<T>`, TS `Promise<T>`.
- **Events:** a `Flow<T>` property or function → Dart `Stream<T>`, TS subscription (`addListener` returning an unsubscribe handle).
- **Errors:** any `Throwable` → Dart `HenosisException(code, message)`; TS promise rejection with `code`. `code` = the native exception's simple class name.
- **Lifecycle:** each facade class is a **singleton** inside the plugin/module. Constructor may take no args or an Android `Context` (inject `applicationContext`).
- **Output:** `henosis-out/flutter/<package>/` and `henosis-out/react-native/<package>/`, each a complete package with an `example/` app.
- **Commands:** `init`, `inspect`, `doctor`, `generate`, `verify` (section 8).

### Out (record in `docs/roadmap.md`)

- iOS input (XCFramework / Swift), .NET MAUI target
- Native UI views (platform views, camera previews)
- Multiple instances / object handles (v0.1 is singleton-only)
- Callbacks from Dart/TS into native beyond events
- Generics beyond `List`, `Map<String, *>`, `Flow`
- Cancellation of in-flight `suspend` calls
- Publishing to pub.dev / npm

## 6. Config: `henosis.yaml`

Method signatures come from the SDK, not the config. The config only **selects** members. Overloads are disambiguated by parameter types in parentheses.

```yaml
name: sample_sdk                  # base name; drives package names
version: 0.1.0
source:
  aar: ./fixtures/sample-sdk/build/outputs/aar/sample-sdk-release.aar
  # or: maven: com.example:sdk:1.2.0
  # repositories: [https://example.com/maven]
facades:
  - class: com.devstrike.sample.Greeter
    as: Greeter                   # name exposed to Dart/TS (optional)
    constructor: context          # none | context
    methods:
      - greet
      - greetMany
      - fetchProfile
      - divide(Int, Int)          # overload selection
    events:
      - ticks                     # Flow<T> property or fun returning Flow<T>
types:                            # data classes / enums reachable from facades are auto-included;
  include: []                     # list extras here
targets:
  flutter:
    package: sample_sdk
    org: com.devstrike
  react_native:
    package: "@devstrike/sample-sdk"
    module: SampleSdk
```

Validation errors name the exact key path (`facades[0].methods[3]`).

## 7. Type mapping (v0.1)

| Kotlin / Java | Dart | TypeScript | Notes |
| --- | --- | --- | --- |
| `Int`, `Short`, `Byte` | `int` | `number` | |
| `Long` | `int` | `number` | doctor **warns**: values > 2^53 lose precision in JS |
| `Double`, `Float` | `double` | `number` | |
| `Boolean` | `bool` | `boolean` | |
| `String` | `String` | `string` | |
| `T?` | `T?` | `T \| null` | from Kotlin metadata; Java = platform type → treat as nullable, doctor warns |
| `List<T>` | `List<T>` | `T[]` | |
| `Map<String, T>` | `Map<String, T>` | `Record<string, T>` | non-String keys → doctor error |
| `ByteArray` | `Uint8List` | `ArrayBuffer`* | *if TurboModule codegen can't type it directly, use base64 `string` and convert in the TS wrapper; document the choice |
| `data class` | immutable class + `copyWith`, `==`, `hashCode`, `toString` | `interface` (readonly fields) | crosses as a map |
| `enum class` | `enum` | string union | crosses as name string |
| `suspend fun` | `Future<T>` | `Promise<T>` | |
| `Flow<T>` | `Stream<T>` | `addListener(cb): Unsubscribe` | one channel/event per declared event |
| `Unit` | `void` / `Future<void>` | `void` / `Promise<void>` | |
| anything else | — | — | doctor **error** with the member path |

Sync (non-suspend) methods still return `Future`/`Promise` across the bridge in v0.1.

## 8. CLI

| Command | Behavior |
| --- | --- |
| `heno init <aar-or-coords>` | Parses the SDK, writes a starter `henosis.yaml` with every public class commented out |
| `heno inspect [--json]` | Prints the public API tree; each member tagged `ok`, `warn`, `unsupported` |
| `heno doctor` | Validates config + types; exit code 1 on any error; one line per finding with a fix hint |
| `heno generate [--target flutter,rn] [--out dir] [--emit-ir]` | Runs doctor, then writes packages; `--emit-ir` also writes `ir.json` |
| `heno verify` | Runs `flutter build apk --debug` in the Flutter example and `./gradlew assembleDebug` in the RN example; reports pass/fail per target |

Exit codes: 0 ok, 1 validation error, 2 toolchain missing, 3 build failed.

## 9. Sample SDK fixture (`fixtures/sample-sdk`)

Our own Kotlin Android library. It must exercise **every** row in section 7 and every lifecycle option. Minimum:

- `Greeter(context: Context)` with: `greet(name: String): String`, `greetMany(names: List<String>): Map<String, String>`, `suspend fun fetchProfile(id: Long): Profile?`, `divide(a: Int, b: Int): Double` (throws `ArithmeticException` on zero) and an overload `divide(a: Double, b: Double)`, `val ticks: Flow<Int>`, `echoBytes(data: ByteArray): ByteArray`
- `data class Profile(val id: Long, val name: String, val tags: List<String>, val level: Level, val avatar: ByteArray?)`
- `enum class Level { BRONZE, SILVER, GOLD }`
- One deliberately **unsupported** member (e.g. `fun <T> generic(x: T): T`) to test doctor.

## 11. Engineering conventions

- Small, focused commits with conventional messages (`feat(parser): ...`, `fix(gen-flutter): ...`).
- Every generator change updates its golden files in the same commit (`./gradlew updateGolden`, review the diff).
- Public functions in `henosis-core` get KDoc.
- No network access in unit tests; Maven tests use a local file repository fixture.
- Generated Kotlin uses `CoroutineScope(SupervisorJob() + Dispatchers.Main.immediate)` owned by the plugin/module and cancelled on detach/invalidate; results are delivered on the main thread.
- Keep the IR target-agnostic: no Flutter or RN concepts inside `henosis-core`.
